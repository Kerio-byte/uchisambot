# Решения совета 15.10.2026 и что с ними стало

Совет (дизайнер, маркетолог, SEO) собирался 15 октября в два раунда; полные тексты —
шесть файлов раундов `round1_*` и `round2_*` (хранятся вне сайта, в архиве комнат).
Решения жили в переписке и в README по частям. Этот файл — их поимённая сверка с сайтом
25.10.2026: построчно, с указанием, где решение держится и чем проверяется.

Проверка сделана заново, по факту дерева и браузера, а не по памяти о коммитах.

## Отклонения, у которых есть причина

1. **Значки площадок лежат у нас, а не горячей ссылкой с их сайтов** (совет раунда 2:
   «хотлинки оставить»). Причина: Startup Fame отдаёт файл с кодом 200, но Chrome режет
   ответ как ORB — значок молча прятался своим `onerror`, и площадок было видно 7 из 8.
   Ссылка по-прежнему ведёт на площадку.
2. **Шрифтовой бюджет 160 КБ вместо 100.** Совет считал бюджет для двух языков. Девять
   письменностей (латиница, кириллица, деванагари, вьетнамский) в 100 КБ не влезают;
   замер и порог закреплены в `landing-fonts.py`.
3. **Липкая кнопка 59 px вместо 56.** Кнопка внутри — 46 px (порог 24×24 с запасом на
   палец), поля 6+6 и рамка дают 59. Уменьшать кнопку ради цифры 56 смысла нет.

## Что решает владелец (не совет и не я)

Цвет нижней полосы; чип предмета в герое; значки площадок в одну строку или в две;
судьба карточки-телефона в герое; идеи «при желании».

## Чем это стережётся

- `landing-sweep.py` — 2775 статических проверок, в том числе весь блок «сверка с
  решениями совета» (17.10) и семь новых: мобильный порядок героя, кнопка героя вне
  показа, описание значков в README против факта (25.10), правило шапки на телефоне
  («mobile header row», 25.10 — ряд шапки больше не упирается в поля на 320 px),
  перенос ряда шапки («header row wraps»), запрет сжатия логотипа/меню/переключателя
  («header no shrink») и отступ якоря по настоящей высоте шапки
  («anchor padding fits header») — три последние закрывают настройку браузера
  «минимальный размер шрифта», которая растит только текст.
- Браузерные батареи: `landing-first-screen.py` (кнопка выше сгиба, 252), `landing-tablet-page.py`
  (1804), `landing-landscape-page.py` (956), `landing-visual-pass.py` (вид и числа по девяти),
  `landing-page-lang.py` (метки и словари), `landing-fonts.py` (бюджеты шрифтов).
- Ряд шапки на телефоне меряется не в одном движке и не в одном состоянии:
  `landing-header-engines.py` (25.10.2026) — Chromium, Firefox и WebKit × девять языков ×
  шесть ширин обычной страницы (320/340/420/760/761/900, где 761 — первая ширина без
  правила 25.10 и первая, которой не было ни в одной батарее) плюс интервалы WCAG 1.4.12
  на 320/340/420 — 972 проверки, 0 провалов; без правила 25.10 та же батарея даёт 5 красных
  (pt 317.5, id 313.5, uk 324.2 и документ 324 px на экране 320).
- Форма связи на телефоне меряется с ОТКРЫТОЙ клавиатурой: `landing-keyboard-form.py`
  (25.10.2026) — девять языков × три телефона (320×568, 360×800, 390×844), экран урезается
  до «экран минус клавиатура» (308/500/500 px): нет прокрутки вбок, поле видно не меньше
  чем на 60%, липкая полоса не показана над формой, кнопка «отправить» в кадре, текст
  переживает открытие и закрытие клавиатуры — 244 проверки, 0 провалов.

## Чего эта сверка не доказывает

Что владелец согласен с отклонениями из раздела выше — они записаны как факт с причиной,
а не как разрешение. И что решения совета были верными: проверено исполнение, не качество.
